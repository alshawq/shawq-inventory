# SHAWQ Inventory — إدارة المخزون والمبيعات

نظام Full-Stack بواجهة عربية RTL لإدارة المنتجات والمستودعات والموردين والمشتريات والفواتير والتقارير.

## المميزات المنفذة

- تسجيل دخول المدير بكلمة مرور مشفرة (bcrypt) وجلسة JWT مدتها 8 ساعات.
- إدارة المنتجات (إضافة/تعديل/أرشفة) مع SKU فريد وسعر البيع والتكلفة وحد التنبيه.
- إدارة المستودعات والموردين (إضافة/تعديل/حذف مع حماية العلاقات).
- تسجيل المشتريات وإضافة الكمية للمخزون في معاملة PostgreSQL ذرية.
- إنشاء فواتير بيع وخصم الكمية مع قفل صف المنتج لمنع البيع فوق المتاح.
- سجل لحركات المخزون، وبنود محفوظة للفواتير والمشتريات (واجهة API).
- تقارير مبيعات، ومجمل ربح (قبل المصاريف والضرائب)، ومؤشرات المخزون، وتنبيهات الحد الأدنى.
- تصدير قائمة المنتجات CSV، والبحث في الجداول، وتصميم متجاوب.
- دعم عدة بنود في فاتورة واحدة عبر API؛ واجهة إنشاء الفاتورة الحالية تضيف بندًا واحدًا لكل عملية.

## المتطلبات

Node.js 20+، PostgreSQL 15+، أو Docker Desktop لتشغيل قاعدة البيانات.

## التشغيل على Windows PowerShell

1. فك الضغط وافتح مجلد `shawq-inventory` في VS Code.
2. شغّل PostgreSQL وأنشئ قاعدة `shawq_inventory`، أو استخدم Docker:

```powershell
Copy-Item .env.example .env
# غيّر POSTGRES_PASSWORD في .env
# Docker فقط:
docker compose up -d
```

3. إعداد الخادم:

```powershell
cd server
Copy-Item .env.example .env
notepad .env
npm.cmd install
npm.cmd run dev
```

عدّل `server/.env` قبل التشغيل:
- `DATABASE_URL`: إذا استخدمت Docker: `postgresql://shawq:YOUR_PASSWORD@localhost:5433/shawq_inventory`.
- `JWT_SECRET`: نص عشوائي طويل لا يقل عن 32 حرفًا.
- `ADMIN_EMAIL`: بريد مدير النظام.
- `ADMIN_PASSWORD`: كلمة مرور قوية لا تقل عن 12 حرفًا.
- `CORS_ORIGIN`: رابط الواجهة، افتراضيًا `http://localhost:5173`.

ينشئ الخادم الجداول تلقائيًا ويضيف حساب المدير عند التشغيل الأول. **لا توجد بيانات تجريبية أو كلمة مرور ثابتة في الكود.**

4. افتح نافذة PowerShell ثانية لتشغيل الواجهة:

```powershell
cd client
npm.cmd install
npm.cmd run dev
```

افتح `http://localhost:5173` وسجل الدخول ببريد المدير وكلمة المرور التي وضعتها.

## نقاط API

`POST /api/auth/login` — دخول.
`GET /api/health` — فحص قاعدة البيانات.
`GET /api/state` — بيانات لوحة التحكم (يتطلب Bearer token).
`POST/PUT/DELETE /api/products` — منتجات (التعديل والحذف يستخدمان `/api/products/:id`).
`POST/PUT/DELETE /api/suppliers` — موردون.
`POST/PUT/DELETE /api/warehouses` — مستودعات.
`POST /api/invoices` — فاتورة بيع، مثال: `{"customer":"عميل","items":[{"productId":1,"quantity":2}]}`.
`GET /api/invoices/:id` — تفاصيل فاتورة ببنودها.
`POST /api/purchases` — شراء، مثال: `{"supplierId":1,"items":[{"productId":1,"quantity":5}]}`.
`GET /api/movements` — سجل حركات المخزون.

## ملاحظات مهمة قبل الاستخدام التجاري

هذا إصدار متكامل الوظائف الأساسية للمشروع، لكنه **ليس نظام ERP إنتاجيًا معتمدًا**. لم يتم التحقق من تشغيله في هذه البيئة لعدم توفر تثبيت الحزم وقاعدة PostgreSQL؛ اختبره محليًا قبل الاستخدام. يتطلب الإنتاج إعداد HTTPS، نسخ احتياطي آلي، صلاحيات متعددة المستخدمين إن لزم، اختبارات تكامل، مراقبة وتشغيل احترافي. لا يدعم حتى الآن المرتجعات والضرائب التفصيلية والمدفوعات والفواتير الإلكترونية الرسمية أو نقل المخزون بين المستودعات. لا تستخدم الفواتير الصادرة منه كفواتير ضريبية رسمية دون مراجعة المتطلبات المحلية.

الأسعار بالدينار الأردني، والأرباح المعروضة هي مجمل الربح وليس صافي الربح.
